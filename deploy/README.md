# 云端部署与浏览器离线使用

适用于个人使用：同一个密码、同一套笔记，可在多台设备访问。不是多用户隔离服务。

## 部署

服务器需要 Docker Compose，域名的 DNS 指向服务器，开放 80/443 端口。在项目根目录创建 `.env`（不要提交）：

```dotenv
OUTLINER_DOMAIN=notes.example.com
OPENOUTLINER_PASSWORD=替换为足够长的随机密码
```

运行 `docker compose up -d --build`，访问 `https://你的域名`，输入密码。Caddy 自动申请 HTTPS 证书。应用端口不直接公开；SQLite 使用命名卷持久保存。第一次部署前如需迁移旧数据，请停止旧应用后复制数据库，或在网页中导入原有 OPML。

不使用 Docker 时：Node >=25，运行 `npm ci && npm run build`，设置 `OPENOUTLINER_HOST=0.0.0.0`、`OPENOUTLINER_PASSWORD`、`OPENOUTLINER_DB` 和 `NODE_ENV=production`，再运行 `npm start`。必须在前面配置同域 HTTPS 反向代理。

生产模式的登录 Cookie 仅通过 HTTPS 发送，30 天过期，密码改变后旧会话失效。浏览器已下载的数据仍可离线读取；请只在自己的设备使用。默认只监听本机且未设密码的开发服务保持免登录。

## 离线与同步

- 首次登录下载所有笔记。首次页面缓存完成后，即可断网重新打开。使用较新的 Chrome、Edge、Safari 或 Firefox，且必须是 HTTPS（localhost 开发例外）。
- 浏览器以 IndexedDB 持久保存 SQLite 数据，业务逻辑与服务端共用。新增、编辑、移动、删除、标签、导入导出、撤销重做都在本机执行。
- 只有本机存储事务成功才确认保存。防止同源多标签页竞争写入的 Web Locks 是必需能力。
- 修改后约 700 ms 发起同步；恢复连接、重新聚焦，以及可见页面每 15 秒重试。网页关闭或设备休眠时不保证后台同步。
- 上传的是相对于上次云端版本的记录差异；目前拉取返回全量笔记快照，适合个人笔记规模，尚非大规模增量分页同步。单次请求上限 32 MB。
- 不同字段和不同记录的修改自动合并。同一字段或层级关系冲突暂停同步，完整保留本机和冲突时云端快照。
- 左下角“同步状态”可选择云端或本机整套版本。被替代的版本保留在本机恢复备份中，可下载 JSON。选择本机整套版本会覆盖冲突快照中的其他云端变化；期间云端再次改变会重新检查冲突。
- “恢复备份”可以恢复下载文件的 `local` 版本。其他保留版本可在同步面板的“保留的版本”下拉框中选择并下载，然后导入。导入前当前数据也会备份。
- 撤销历史仅在本设备维护；应用远端变化时清空旧历史，防止撤销覆盖其他设备的数据。
- 首版不离线下载外链和远程图片。应用页面、字体、图标与 SQLite WASM 会缓存。开发模式不注册 Service Worker，请用生产构建验证离线重新打开。
- Service Worker 更新会等待旧页面关闭后生效。升级部署后关闭该站点所有标签页再打开；旧缓存保留用于仍在使用旧版本的页面。
- 清除网站数据、浏览器隐私模式退出或系统回收存储可能删除本地数据。未同步内容请先下载恢复备份。

## 数据备份

浏览器副本不代替服务器备份。部署者应为 `outliner-data` 卷设置定期备份。最简单的安全做法：停止 `app` 服务后备份整个卷，再启动；在线备份应使用 SQLite Backup API，不要只复制正在写入的主数据库文件而遗漏 WAL。升级前先备份。

## 本地验证

```sh
npm test
npm run typecheck
npm run build
OPENOUTLINER_PORT=4318 OPENOUTLINER_DB=/tmp/openoutliner-test.sqlite npm start
```

打开 `http://127.0.0.1:4318`，等待首次缓存完成，在浏览器开发者工具切换 Offline，编辑后查看“已保存到本机”，刷新确认内容仍在，恢复网络后检查“已同步”。该测试使用独立数据库，不影响个人笔记。

浏览器 SQLite 使用 [sql.js](https://sql.js.org/documentation/Database.html)，WASM 随应用构建，无运行时第三方 CDN 依赖。

## 首次同步提示“节点父级冲突”

旧版本的同步校验会误拒绝一种历史数据：删除子节点后，将仍然存在的父节点移到其他工作区。已删除节点仍保留原工作区与父级信息，旧校验却要求它与父级的当前工作区一致。修复后的校验保留这些历史记录，只要求有效节点与其直接父级的关系正确；有效节点的跨工作区父级、已删除父级以及循环层级仍会被拒绝。

更新服务器代码后，必须重新构建前后端。使用本仓库 Compose 配置时运行 `docker compose up -d --build`；直接运行 Node 时执行 `npm run build` 后重启应用进程。

浏览器可能仍在运行旧版离线缓存：部署后先联网打开页面，等待新资源下载完成，再关闭该站点的所有标签页（包括安装的独立应用窗口），重新打开。若仍显示旧错误，可再完成一次上述关闭、打开流程。无需删除服务端数据库，也不要为了更新代码清空 IndexedDB 中的未同步数据。

若新版仍提示父级冲突，错误会包含具体节点名称，以及“父级属于其他工作区”或“父级已删除”。这表示有效节点关系需要进一步检查，不能仅凭旧截图断定原因。

## 已部署新代码但浏览器仍显示旧错误

可以先用无痕窗口访问同一网址；无痕窗口不沿用原窗口的离线缓存。如果无痕窗口正常，请保留原窗口的 IndexedDB 数据，不要使用“清除所有网站数据”。

已部署应用更新入口后，可访问 `https://你的域名/api/app-recovery`。这个地址绕过旧 Service Worker 的页面缓存，不需要登录，只展示构建信息。关闭该站点其他窗口，再点击“更新应用缓存并重新打开”。该操作只注销本应用的 Service Worker、清理 `openoutliner-` 开头的应用缓存，不删除 IndexedDB 或登录 Cookie。API 数据仍要求正常的登录权限。

在尚未部署更新入口的版本中，Chrome 可打开开发者工具 → Application（应用）→ Service Workers（服务工作线程），对该域名点击 Unregister（注销），再关闭该站点全部窗口并重新打开。不必删除数据库或重建服务器。

Node 部署请确认重启的是项目中运行 `dist/backend/server/index.js` 的进程；如果 Nginx 直接提供静态文件，其 root 应指向同一项目的新 `dist/web`。设置 `OPENOUTLINER_PASSWORD` 后须重启 Node，使密码保护生效。
